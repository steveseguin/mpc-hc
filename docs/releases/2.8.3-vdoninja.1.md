# MPC-HC 2.8.3 — VDO.Ninja Edition 1

The first VDO.Ninja edition adds WebRTC viewing to MPC-HC, including direct WHEP
endpoints and VDO.Ninja's asynchronous data-channel `whepSettings` handoffs.

## Download and run

Download **MPC-HC.2.8.3-vdoninja.1.x64.zip**, extract the entire folder, and run
`mpc-hc64.exe`. This is a portable Windows x64 release with LAV Filters,
translations, MPC Video Renderer and the required Visual C++ runtime DLLs.
Settings are stored beside the executable. No installer is required.

WebRTC requires **Windows 10/11** and the
[Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/).
The runtime is installed separately. The download is unsigned.

## Open a stream

Use **File > Open File/URL** (`Ctrl+O`) and paste a link, for example:

- VDO.Ninja: `https://vdo.ninja/?view=STREAM_ID&password=PASSWORD&cleanoutput&autostart`
- WHEP: `https://your-server.example/live/STREAM_ID/whep`
- Meshcast WHEP: `https://region.meshcast.io/whep/STREAM_ID`
- Arbitrary WHEP path: `whep+https://your-server.example/your-endpoint`
- Local HTTP: `whep+http://192.168.1.10:8889/STREAM_ID/whep`

Use the actual endpoint supplied by your streaming service. For WHEP bearer
authentication, append `#token=URL_ENCODED_TOKEN`.

MPC's volume/mute, play/pause, Stop, fullscreen and shortcuts control playback.
Stop disconnects; Play reconnects. H.264 and Opus are preferred for direct WHEP,
with VP8, VP9, AV1 and mono/stereo Opus sources also supported by compatible
WebView2 runtimes.

## Scope and limitations

WebRTC uses **embedded WebView2** for decoding, video and audio. MPC's DirectShow
filters, shaders, subtitles, capture and audio-device settings do not apply to
WebRTC; browser audio uses the Windows default output device. Normal file
playback continues through MPC's existing pipeline.

Direct WHEP requires browser CORS support, including `Origin: null`, and exposed
`Location` response headers for session cleanup. This initial receiver does not
implement trickle ICE, ICE restart, automatic retry or server-provided TURN
configuration. VDO.Ninja handles its own signaling and network configuration.

Validation covers the x64 application with synthetic H.264/VP8/VP9/AV1 video,
Opus audio, player controls, fullscreen, stream/file switching, session cleanup,
HTTP errors, WHEP counter-offers, VDO.Ninja viewing and asynchronous handoffs.
The WHEP endpoint was local; a live Meshcast deployment and long-duration or
restrictive-network playback have not been validated.

See the [README](https://github.com/steveseguin/mpc-hc#open-a-vdoninja-or-whep-stream)
and [WebRTC documentation](https://github.com/steveseguin/mpc-hc/blob/2.8.3-vdoninja.1/docs/WebRTC.md)
for details. Source is available at tag `2.8.3-vdoninja.1`; use
`git clone --recursive --branch 2.8.3-vdoninja.1 https://github.com/steveseguin/mpc-hc.git`
to include the pinned dependency sources. Build instructions are in `docs/Compilation.md`.
