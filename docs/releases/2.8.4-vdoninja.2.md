# MPC-HC 2.8.4 - VDO.Ninja Edition 2

Fixes the shrinking-window problem during VDO.Ninja and WHEP playback. Opening
a stream, adaptive resolution changes and reconnecting now preserve your chosen
window size. The embedded viewer fills the video area and handles aspect ratio
and scene layout. Manual resizing and fullscreen remain available.

Automatic update checks are off by default, including fresh settings. Manual
checks and automatic checks you explicitly enable use **steveseguin/mpc-hc**;
both version feeds and the download button stay on this fork.

## Download and run

Download [**MPC-HC.2.8.4-vdoninja.2.x64.zip**](https://github.com/steveseguin/mpc-hc/releases/download/2.8.4-vdoninja.2/MPC-HC.2.8.4-vdoninja.2.x64.zip)
([SHA256 checksum](https://github.com/steveseguin/mpc-hc/releases/download/2.8.4-vdoninja.2/MPC-HC.2.8.4-vdoninja.2.x64.sha256)).
Extract the entire ZIP into a separate writable folder and run `mpc-hc64.exe`.
Keep the included `mpc-hc64.ini` beside the executable to keep player settings
portable. You can keep this separate from your existing MPC-HC installation.
The package includes LAV Filters, MPC Video Renderer, translations and Visual
C++ runtime DLLs. The download is unsigned.

### WebView2 setup for VDO.Ninja and WHEP

WebRTC playback requires **Windows 10/11 and the Microsoft Edge WebView2 Runtime**.
The runtime is the embedded browser engine used to play these streams and is
**not included in the ZIP**. Ordinary file playback does not need it.

1. Open [Microsoft's WebView2 downloads](https://developer.microsoft.com/en-us/microsoft-edge/webview2/).
2. Choose **Evergreen Bootstrapper** and run it. For an offline installation on
   an Intel/AMD 64-bit PC, choose **Evergreen Standalone Installer > x64**.
3. Finish installation, close MPC-HC completely, then reopen `mpc-hc64.exe`.

**Copying one DLL into the player folder is not enough.** The WebView2 loader is
already built into MPC-HC; the complete runtime is still required. You do not
need the WebView2 SDK or to install the Edge browser itself; see
[Microsoft's WebView2 FAQ](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/end-user-faq#will-uninstalling-microsoft-edge-make-webview2-stop-working).

For old Windows installations, check your version with **Win+R > `winver`** and
compare it with Microsoft's [supported Windows versions](https://learn.microsoft.com/en-us/microsoft-edge/webview2/#supported-windows-versions).
See the [current setup and troubleshooting guide](https://github.com/steveseguin/mpc-hc/blob/develop/docs/WebRTC.md#webview2-setup-and-troubleshooting)
for installation permissions, separate player settings, and the advanced
Fixed Version runtime-folder option. A local runtime needs the complete package
and explicit configuration; simply dropping it beside the player is insufficient.

## Open a stream

Use **File > Open File/URL** (`Ctrl+O`) and paste your viewing link:

- VDO.Ninja: `https://vdo.ninja/?view=STREAM_ID&password=PASSWORD&cleanoutput&autostart`
- WHEP: `https://your-server.example/live/STREAM_ID/whep`
- Meshcast: `https://region.meshcast.io/whep/STREAM_ID`
- Arbitrary WHEP path: `whep+https://your-server.example/your-endpoint`

Volume/mute, play/pause, Stop and fullscreen control the viewer. Stop disconnects;
Play reconnects. H.264, VP8, VP9, AV1 and mono/stereo Opus remain supported by
compatible runtimes, along with VDO.Ninja's data-channel `whepSettings` handoffs.

## Validation and scope

Validation includes a live hosted VDO.Ninja stream, sustained window-size checks,
manual resizing, fullscreen return and reconnect. Synthetic WHEP tests change
the encoded video between 160x90, 1280x720, 360x640 and 640x360 while checking that
neither the window nor browser viewport shrinks. The full x64 suite also covers
all four video codecs, Opus, player controls, normal H.264/AAC file playback,
HTTP errors, cancellation, session cleanup, WHEP counter-offers and asynchronous
VDO.Ninja-to-WHEP handoffs.

WebRTC still uses embedded WebView2. DirectShow filters, native video-frame
sizing, shaders, subtitles, capture and MPC audio-device settings do not apply
to these streams. Browser audio uses the Windows default output device.
Direct WHEP requires browser CORS; trickle ICE, automatic retry and
server-provided TURN configuration are not implemented. Live Meshcast endpoints,
restrictive networks, long-duration sessions and x86 builds remain unverified.
