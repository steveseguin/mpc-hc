# MPC-HC 2.8.4 - VDO.Ninja Edition 2

Fixes the shrinking-window problem during VDO.Ninja and WHEP playback. Opening
a stream, adaptive resolution changes and reconnecting now preserve your chosen
window size. The embedded viewer fills the video area and handles aspect ratio
and scene layout. Manual resizing and fullscreen remain available.

Automatic update checks are off by default, including fresh settings. Manual
checks and automatic checks you explicitly enable use **steveseguin/mpc-hc**;
both version feeds and the download button stay on this fork.

## Download and run

Download **MPC-HC.2.8.4-vdoninja.2.x64.zip**, extract the entire folder, and run
`mpc-hc64.exe`. The portable package includes LAV Filters, MPC Video Renderer,
translations and Visual C++ runtime DLLs. Settings are stored beside the player.
WebRTC requires Windows 10/11 and the
[Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/).
The download is unsigned.

Use **File > Open File/URL** (`Ctrl+O`) and paste your viewing link:

- VDO.Ninja: `https://vdo.ninja/?view=STREAM_ID&password=PASSWORD&cleanoutput&autostart`
- WHEP: `https://your-server.example/live/STREAM_ID/whep`
- Meshcast: `https://region.meshcast.io/whep/STREAM_ID`
- Arbitrary WHEP path: `whep+https://your-server.example/your-endpoint`

Volume/mute, play/pause, Stop and fullscreen control the viewer. Stop disconnects;
Play reconnects. H.264, VP8, VP9, AV1 and mono/stereo Opus remain supported by
compatible runtimes, along with VDO.Ninja's data-channel `whepSettings` handoffs.

## Validation and scope

Validation includes a live hosted VDO.Ninja stream, sustained window-size checks,
manual resizing, fullscreen return and reconnect. Synthetic WHEP tests change
the encoded video between 160x90, 1280x720, 360x640 and 640x360 while checking that
neither the window nor browser viewport shrinks. The full x64 suite also covers
all four video codecs, Opus, player controls, normal H.264/AAC file playback,
HTTP errors, cancellation, session cleanup, WHEP counter-offers and asynchronous
VDO.Ninja-to-WHEP handoffs.

WebRTC still uses embedded WebView2. DirectShow filters, native video-frame
sizing, shaders, subtitles, capture and MPC audio-device settings do not apply
to these streams. Browser audio uses the Windows default output device.
Direct WHEP requires browser CORS; trickle ICE, automatic retry and
server-provided TURN configuration are not implemented. Live Meshcast endpoints,
restrictive networks, long-duration sessions and x86 builds remain unverified.
